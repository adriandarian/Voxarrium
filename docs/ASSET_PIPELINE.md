# Asset pipeline

M9 adds dedicated local Blender citadel architecture. Its final additive keep pavilion preserves every earlier face and semantic bound, with 95,296 hero/11,020 resident triangles in the same 17/6 material batches and zero image textures. The diagnosed full-foot bearing correction changes only the new annulus inner radius; both isolated factory exports and exact predecessor files are preserved. [CITADEL](CITADEL.md) records editable source, generator/export commands, imported dimensions, material batches, roof/collision metadata, provenance and focused verification. Hero detail uses the existing bounded GLB cache/scheduler and area leases; lightweight skyline context is a resident asset with explicit renderer lifetime. The domestic district kit, older shipped assets and original reference hashes remain unchanged. Native runtime visual/performance acceptance is recorded separately from export success.

M7 reuses the unchanged M4.1 `district.kit` and all four older shipped GLBs. No Blender export or image generation is required for its two districts. Controlled meter-scale facade, roof, floor-height, corner, shopfront and attachment parameters are serializable under `src/simulation/urban-*` plus the two district modules. The renderer instances the original all-side kit; it does not modify GLB bytes or source-image hashes. Locally generated paving pigment and accepted botanical geometry have finite cache identities and explicit district lease ownership. Named unseen trades, compounds and the Lower Canal loading dock are documented assumptions, not measurements from the concept image.

Author/source: `assets/source/`; generator scripts: `tools/blender/`; local generated fixtures: `.local/assets/`; final reviewed runtime files: `public/assets/`. Reference images remain documentation and must not inflate the runtime build.

M0 runs `npm run blender:fixture`. The launcher finds BLENDER_PATH, Blender on PATH, or standard installation locations, then launches an isolated background factory session. It does not touch an open scene or existing .blend file. It exports a labeled 1 m cube to `.local/assets/scale-fixture.glb`. This is a pipeline calibration asset, NOT a cottage or art-quality proof.

M1 extends that generator with three asymmetric colored marker meshes. Blender X at (1.5,0,0) imports as glTF +X; Blender Y at (0,1.5,0) imports as -Z; Blender Z at (0,0,1.5) imports as +Y. Colors come from Principled BSDF Base Color, not viewport display color. The browser validates cube bounds, each marker center and dominant color before placement, then shows the original GLB materials.

The verified M1 export is vendored at `public/assets/diagnostics/scale-fixture.glb`; provenance/checksum/counts live in `assets/manifest.json`. Normal launches do not need Blender. To revise the fixture, export to `.local/assets/`, inspect it, copy the reviewed GLB into the diagnostic asset path, update its manifest hash and run tests/check/browser capture. Do not silently update the manifest to accept an unexplained mismatch. The cube uses a separate 1 m collision proxy; tiny axis markers are non-colliding diagnostics. Runtime checks and `artifacts/m1/blender-calibration.png` establish actual Three.js scale/orientation/material behavior.

Use one meter scale, apply relevant mesh transforms deliberately, preserve armature/animation semantics, and make pivots meaningful (door hinge, tree base, module snap origin). Confirm axis orientation in the runtime. Name parts stably; add simple collision proxies separately. Full facade, roof thickness, backs and sides are required at player distance.

After one hero cottage and bridge are approved at close range, derive a small kit: roof pieces, plaster/timber walls, openings, chimney, stone, fences and props. Avoid mass-producing generic low-poly assets before quality review.

Export GLB/glTF 2.0; keep materials compatible with the tested runtime. Bake Blender-only procedural materials when needed, without baking a fixed sun into base color for a day/night world. Optimize through measured deduplication, geometry simplification and appropriate texture compression. Meshopt/Draco/KTX2 require corresponding loaders and verified tradeoffs; do not apply every compressor by default.

Each shipped asset record needs ID, source/generator, license/provenance, bounds/scale, triangle/material/texture counts, collision/LOD policy and preview views. Do not assume user-supplied reference art carries redistribution or commercial rights. No automatic asset downloads or purchases.

The launcher is cross-platform. Set BLENDER_PATH to the executable path if discovery fails; do not install an MCP bridge or expose Blender on a network port for this bootstrap.

## M2 authored rural assets

`npm run blender:rural` invokes `tools/blender-rural.mjs` and `tools/blender/rural_hero.py` in an isolated local Blender factory session. The editable source is `assets/source/rural-hero.blend`; exports are `public/assets/rural/{cottage,shed,bridge}.glb`. The local export report is `.local/rural-asset-report.json`; the inspected report is retained as `assets/source/rural-hero.report.json`. Preserve deliberate manual Blender edits before regeneration. After a diagnosed asset change, compare runtime views, then update the asset manifest hashes and retained report.

The source preserves semantic parts; exported meshes are joined by material, with named material sets and part bounds retained in metadata. Cottage and shed origins are at ground center, bridge origin at deck-top center. Blender X/Y/Z convert to glTF X/-Z/Y without a runtime corrective rotation or scale. Original GLB materials remain in use. Separate simplified collision proxies are authored in `src/simulation/rural.ts`. Doors are closed collision boundaries, with climbable external thresholds; no explorable interior is claimed.

The cottage has all four elevations, roof tiles and underside/eaves, recessed glazed windows, dimensional doors, timber, stone plinth, chimney and restrained barrel props. Bridge rails, deck, trestles and underside exist independently of the reference camera. The local GLTFLoader tests and inspected `artifacts/m2/final/` camera captures validate import and geometry; they do not confer owner art approval.

Terrain, water and the reusable vegetation library are authored runtime geometry under `src/render/rural.ts` with serializable terrain/layout under `src/simulation/`. Four small deterministic pigment maps are generated by `landscape-materials.ts`; no source-image pixels are sampled. Ecological patch placement respects authored paths, buildings, crop/garden areas and stairs. Provenance and instance counts are recorded in the manifest. Remaining repetition, edge quality and reference-fidelity differences are listed in the review log.

## M4 modular district kit

`npm run blender:district` runs `tools/blender-district.mjs` and `tools/blender/district_kit.py` in a local isolated Blender factory session. Editable source: `assets/source/district-kit.blend`; retained export report: `assets/source/district-kit.report.json`; shipped library: `public/assets/district/district-kit.glb`. Preserve any manual source edits before regeneration. No purchased/downloaded asset or reference-image pixels are used.

The original M4 export contained 24 modules, 111 primitive meshes, 94,244 triangles and 28 materials in 4,674,396 bytes. M4.1's actual Blender 5.2.1 LTS export contains 32 stable modules, 131 primitives, 99,192 triangles and the same 28 materials in 4,925,292 bytes. The eight additions are independent hinged shutters, bakery/pottery/produce/textile goods, basket, bench and mooring post. The standard window now has separate shutter leaves; stall goods no longer duplicate a single produce display. Existing plaster/timber walls, stone foundation, roof forms, recessed openings, chimneys, balconies, signs, awnings, stairs, railings and civic parts retain their foundation. Origins/axes are meter-scale glTF coordinates; collision is independently authored in the district course. The library bounds in the manifest describe unplaced modules, not the assembled district extent.

Six archetypes compose 27 authored lots with different sizes, floor counts, yaw, roofs, palette emphasis and attachments. The civic hall has an authored raised composition and larger module relationships. Repeated primitives share instanced geometry/material batches. World-coordinate TSL plaster pigment avoids part-boundary UV seams; compatible dimensional timber/roof/stone material treatment follows the cottage palette. Exterior windows glow at night without creating a light per window. Garden communities/window boxes use shared rural botanical geometry and the existing environment adapter.

Actual GLTFLoader tests validate bounds, module IDs, closed sides/roof geometry and composition. M4.1 runtime review views include backs, sides, first-person alley/doorway and eagle-eye under `artifacts/m4-1/final/`, with the prior M4 captures retained under `artifacts/m4/final/`. They establish tested rendering and inspection, not owner art approval. The four older shipped GLBs and original reference hashes remain unchanged.
