`city-core.ts` owns the repeatable 104-point circuit, approximately 3.383 km in horizontal authored length. `npm run stress:core` performs three actual W/Shift circuits per preset from natural spawn, alternating third/first/third-person, with yaw steering every 80 ms. It uses hardware-backed headless Chrome so the owner can use their physical mouse; it asserts the initialized AMD/RDNA2 WebGPU adapter. External owner CPU/GPU workloads are uncontrolled. These measurements are not matched comparisons with historical headed runs and do not measure physical display presentation. It uses no bookmarks, teleports, deterministic stepping or reloads. Timing covers actual rAF samples and page-clock-correlated request/ready/needed/crossing/activation milestones. Ended, fully settled request records export once at existing waypoint/checkpoint readbacks before the fixed 48-entry page ledger can evict them. Their transfer overhead remains in cadence samples. The endpoint merges those records with live reports and checks exported request count against lifecycle loads. Equivalent rural returns compare render/asset/cache ownership, physics, IDs, environment and audio. Raw and forced-GC JS heap are distinct; final export/diagnostic cleanup, GC, optional heap graphs and render-list aging occur outside cadence windows. JS heap is not VRAM and browser wall intervals are not GPU execution time.

Capture protocol v2 stages completed reports into a bounded plain-data queue and drains exact chronology in chunks of at most 32 KiB / 64 rows during ordinary W-held steering. Remaining endpoint chunks drain before cadence sampling ends. No added junction wait or timing interval is excluded. Protocol file hashes are recorded separately from the frozen runtime source.
